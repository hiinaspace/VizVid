VizVid loudness fork

A fork of VizVid by Hiina. It adds a loudness gain to each playlist entry, so loud videos can be turned down without touching the volume slider. Source and releases.

VPM listing URL: https://hiinaspace.github.io/VizVid/index.json (add to VCC)

Install

  1. Add the listing above to VCC or ALCOM (Settings, Packages, Add Repository).
  2. Keep the upstream listing, https://xtlcdn.github.io/vpm/, added too. VizVid needs vrcw-foundation and lazyswitch, and those only come from there.
  3. Turn on pre-release packages. In VCC: Settings, Packages, Show Pre-Release Packages. In ALCOM: Settings, Show pre-release packages. The fork's versions end in -loudness.N, which counts as a pre-release.
  4. Open your project, find "VizVid (loudness fork)", and pick the newest 1.8.4-loudness.N version.
  5. If the project already has VizVid, this replaces it. Back up the project first.

Check that it worked

Go through these in order. Each one says what you should see and what it means if you do not.

1. The package version in VCC or ALCOM

Right: the project lists "VizVid (loudness fork)" with a version like 1.8.4-loudness.2.

Wrong: it says plain "VizVid" or a version without -loudness. That is upstream's copy. Gains in your playlist will be ignored. Pre-releases are probably off, or the fork listing is missing. Fix that and install again.

2. The Loudness Doctor

In Unity, with your world scene open, choose Tools > VizVid > Loudness Doctor. The full report is written to the Console.

Right: the dialog says PASS. The report says the fork is installed, it is the only VizVid copy, and how many entries are attenuated.

Wrong: a WARN or FAIL line says in plain words what is off: another VizVid copy, a gain array that is empty or too short (those entries play at full volume), unsaved changes, and so on. A warning about YouTube entries at full volume means they were either never baked or are already quiet enough. The file cannot say which.

3. The playlist editor, after importing the JSON

Select the VizVid Frontend object, press "Edit Playlists...", then "Import from JSON" and pick the playlist file. If it asks where to load the playlist, pick "New Playlist" or "Replace Current". Then press "Save" in the playlist editor window.

Right: the Console says [VVMW] Imported N entries ... M had a gain field, with M above zero. The top of the editor window reads Loudness fork ...: X of N entries attenuated (-9.1 to -0.4 dB). Each entry shows its gain in dB beside the slider.

Wrong: if the header does not appear, the fork is not installed (check 1). If M is 0, the JSON has no gain fields and every entry will play at full volume.

4. Save the scene

Press Ctrl+S, then run the Doctor again.

Right: no "unsaved changes" warning, and the gain line matches what the editor header said.

Wrong: an "unsaved" warning means the gains are not in the scene file, so they will not be in your build. Gains are only stored when both the playlist editor's Save and the scene save have happened.

5. In the world: the log line, or your ears

Build and test the world (or upload it), join, and play a playlist entry. Playlist plays only: a video you queue or a URL you paste always plays at full volume.

Right: VRChat's output log, and the in-game debug console, show one line per entry played, like [VizVid] loudness gain -7.16 dB (x0.4385) for entry 12. The log is in %LOCALAPPDATA%Low\VRChat\VRChat\output_log_*.txt on Windows. The video is audibly quieter than the same video at full volume.

Wrong: 0.00 dB (x1) means that entry has no gain. If it adds "no gain array in this world", the gains were not saved into the scene before building (checks 3 and 4). If there is no [VizVid] loudness gain line at all, the world was built with upstream's VizVid or an older build, so build again after check 1.

What upstream updates do

This fork is based on upstream VizVid 1.8.3. A fork version like 1.8.4-loudness.2 counts as older than a final upstream 1.8.4. When upstream publishes 1.8.4 or later, VCC will offer it as an update and may pick it first.

Upstream does not have the gain field. If you update to it, the playlist gains are dropped and every video plays at full volume. Nothing shows an error. Before updating VizVid, check the version still says -loudness afterwards, and run the Loudness Doctor. A new fork version will be published for each upstream release, but not on the same day.

Limits

  • The gain only turns a video down. It never raises it.
  • It applies to playlist entries. Queued videos and typed URLs play at full volume.
  • "Bake YouTube loudness" needs a yt-dlp build that reports YouTube's loudness data. The editor can use one you point it at.
